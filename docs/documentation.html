Project Overview

The VMRF(DU) Institutional Activity Portal is an enterprise-grade web application developed for Vinayaka Mission's Research Foundation (Deemed to be University) to centralize, streamline, and professionalize the documentation, verification, media enhancement, and public broadcast of all institutional activities across its constituent colleges.

Project Name

VMRF(DU) Institutional Activity Management, Verification, Media Studio & Public Broadcast Portal

Background & Need

VMRF(DU) comprises multiple constituent colleges spread across different locations. Each college conducts numerous institutional activities — symposiums, workshops, guest lectures, health camps, cultural events, faculty development programs, and more. Prior to this portal, activity documentation was fragmented across emails, shared drives, and informal WhatsApp communications, leading to:

  • Loss of important activity records and supporting photos
  • Inconsistent documentation quality across colleges
  • No standardized approval and verification process
  • Delays in publishing activities to social media and the institutional portal
  • No audit trail for compliance and accountability
  • Manual, error-prone media preparation for social media captions

Solution

This portal provides a unified platform where College Administrators submit activity details with supporting media, the Registrar Authority verifies and approves them, the Media Editor Studio optimizes photos and generates AI-enhanced captions, and the Office of Registrar provides final executive authorization before multi-platform publishing.

📋 Centralized Documentation

All institutional activities documented in one system with unique reference IDs and QR verification codes.

✅ Multi-Stage Verification

Structured approval workflow ensuring quality and compliance at every stage before publishing.

🎨 AI Media Enhancement

AI-powered caption generation with 12+ professional institutional templates for consistent branding.

📡 Multi-Platform Broadcast

One-click publishing to Instagram, LinkedIn, Twitter/X, and the institutional portal.

Objectives & Goals

Primary Objectives

  1. Standardize Activity Documentation — Enforce consistent data entry with mandatory fields, standardized categories, and required photo documentation across all constituent colleges.
  2. Automate Approval Workflow — Replace email-based approvals with a structured, role-based multi-stage workflow engine with status tracking and audit trails.
  3. Enhance Media Quality — Provide a dedicated Media Editor Studio with AI caption generation and professional templates to ensure all published content meets university branding standards.
  4. Enable Multi-Platform Publishing — Allow one-click broadcast of approved activities to Instagram, LinkedIn, Twitter/X, and the public institutional portal.
  5. Ensure Authenticity — Generate unique reference IDs and QR verification codes for every activity to prevent tampering and enable public verification.
  6. Provide Analytics — Offer KPI dashboards and export reports for institutional performance tracking and management decision-making.
  7. Enforce Accountability — Maintain immutable audit logs for all actions taken in the system for compliance and governance.

System Architecture

Architectural Pattern

The application follows the Model-View-Controller (MVC) architectural pattern as implemented by Laravel, enriched with:

  • RBAC Middleware Layer — All routes protected by role-based authorization checks
  • Data Scope Isolation — College-scoped and department-scoped queries enforced at the service layer
  • Multi-Stage Workflow Engine — Configurable stage-based state machine for activity approval
  • Status Locking Mechanism — Prevents concurrent edits during active review phases
  • Service Layer — AI Phrasing Service abstracted for reuse across submission and media editing

StatusWho Sets ItEditable?Next Action
draftCollege Admin (save draft)✅ YesSubmit → verification_pending
verification_pendingSystem (on submit)❌ NoRegistrar: Approve/Discuss/Reject
discussRegistrar (Stage 1)✅ College Admin can editCollege Admin resubmits → verification_pending
rejectedRegistrar (Stage 1)❌ TerminalSuper Admin override only
media_reviewSystem (Registrar approves)❌ NoMedia Editor processes and submits

editor_discuss 🔓Office of Registrar✅ Media Editor can editMedia Editor revises and resubmits
ready_to_publishSystem (Office of Registrar approves)❌ NoMedia Editor publishes to platforms
published 🎉Media Editor (publishes)❌ FinalPublic gallery, QR verification active

Status Locking Mechanism (Key Design Feature)

Why Status Locking?

When the Media Editor submits a media package to the Office of Registrar for Stage 2 review, the system transitions the activity to registrar_approval status and locks the record. This prevents any concurrent modifications during the executive review, ensuring the Office of Registrar reviews exactly what was submitted. A visual 🔒 padlock indicator appears in all views. When the Office of Registrar sends back for discussion (editor_discuss), the record is automatically unlocked and returned to the Media Editor's queue with the padlock removed (🔓).

Dynamic Workflow Engine

The workflow engine allows Super Admins to configure custom approval workflows with:

  • Named stages with configurable order
  • Role requirements per stage (which role can take action)
  • Specific user assignments for stages (user_ids JSON array)
  • College-specific stage configurations
  • Allowed actions per stage (approve / discuss / reject)
  • Status transitions: what status to set on Approve, Reject, or Discuss
  • Approval conditions (any one approver / all required to approve)
  • Routing rules by category, activity type, or college

  • FR-1.1: The system shall authenticate users via email and password
  • FR-1.2: The system shall enforce role-based access to all pages and actions
  • FR-1.3: The system shall track login IP address and timestamp for each session
  • FR-1.4: The system shall enforce force-password-reset on first login when configured
  • FR-1.5: The system shall block login for locked or suspended accounts

FR-2: Activity Submission

  • FR-2.1: College Admins shall submit activities with at least one photo attached
  • FR-2.2: The system shall auto-generate a unique reference ID in VMRF-YYYY-XXXX format
  • FR-2.3: The system shall auto-generate a cryptographic QR verification hash
  • FR-2.4: The system shall support draft saving before submission
  • FR-2.5: The AI caption generator shall offer at least 12 professional templates
  • FR-2.6: Photo uploads shall be limited to JPG, PNG, WEBP with max size 10MB
  • FR-2.7: PDF uploads shall be limited to max 15MB

FR-3: Approval Workflow

  • FR-3.1: Registrar shall Approve, Discuss, or Reject each pending submission
  • FR-3.2: Discuss and Reject actions shall require mandatory remarks
  • FR-3.3: Every approval action shall create an immutable log entry
  • FR-3.4: Email notifications shall be sent to relevant users on each status transition
  • FR-3.5: In-app notifications shall be created for each workflow action

FR-4: Media Processing

  • FR-4.1: Media Editor shall access all submissions with media_review status
  • FR-4.2: Media Editor shall submit processed packages to Office of Registrar
  • FR-4.3: The system shall lock records on submission to Office of Registrar
  • FR-4.4: The system shall unlock records when Office of Registrar sends for discussion
  • FR-4.5: Media Editor shall be able to download a ZIP media pack

FR-5: Publishing

  • FR-5.1: Media Editor shall publish approved activities to selected platforms
  • FR-5.2: Post URLs shall be stored per platform for record-keeping
  • FR-5.3: Published activities shall appear in the public gallery
  • FR-5.4: QR verification shall be active for all published activities

Security Design

🛡️ CSRF Protection

Laravel's built-in CSRF middleware with @csrf tokens on every form prevents cross-site request forgery attacks.

🔐 Password Security

Bcrypt hashing with configurable rounds. Force password reset mechanism for new users and security events.

🚫 Authorization Checks

abort_if(!canAccess(), 403) enforced in every controller method. 403 page rendered on unauthorized access.

🗂️ Data Isolation

College-scoped and department-scoped queries prevent cross-college data leakage at the database query level.

📁 File Validation

MIME type and file size validation on all uploads. Only whitelisted image and document formats accepted.

🔒 Status Locking

Records in registrar_approval status are locked from modification, preventing concurrent edit conflicts during executive review.

📜 Audit Trail

Immutable approval logs and system audit logs capture every critical action with user ID, IP, timestamp, and before/after values.

🌐 Session Security

Database session driver with encrypted cookies. 120-minute inactivity timeout with automatic logout.

🚨 Account Lifecycle

Account lock, suspend, and deactivate controls prevent unauthorized access. Login IP and timestamp tracked for security audits.

Implementation Details

Deployment Prerequisites

  • PHP 8.2+ with extensions: pdo_mysql, mbstring, xml, curl, gd, zip, fileinfo
  • MySQL 8.0+
  • Composer 2.x
  • Node.js 18+ and npm (for asset compilation)
  • Apache 2.4+ with mod_rewrite enabled
  • XAMPP / WAMP / or production Linux server

Installation Steps

1. Clone Repository & Install Dependencies
Run composer install and npm install to install PHP and Node.js dependencies.
2. Configure Environment
Copy .env.example to .env. Set DB credentials, app key, mail settings, and timezone.
3. Generate Application Key
Run php artisan key:generate to set the application encryption key.
4. Run Migrations
Run php artisan migrate to create all 16+ database tables with proper relationships.
5. Seed Initial Data
Run php artisan db:seed to populate constituent colleges, Super Admin account, and default workflows.
6. Build Assets
Run npm run build to compile Bootstrap, CSS, and JavaScript assets via Vite.
7. Set File Permissions
Ensure storage/ and public/uploads/ are writable by the web server process.
8. Configure Web Server
Point Apache DocumentRoot to the public/ directory. Enable mod_rewrite for clean URLs.

Key Business Logic

AI Caption Generation

The AI Phrasing Service provides 12+ professional institutional templates with dynamic context injection. Templates include placeholders for {{event_title}}, {{college_name}}, {{event_date}}, and {{hashtags}} that are replaced at generation time. Templates cover different tones: formal institutional, celebratory, informative, and community-focused.

Reference ID Generation

Each activity receives a unique reference ID in the format VMRF-{YEAR}-{SEQUENTIAL_NUMBER} (e.g., VMRF-2026-0042) auto-generated upon first submission.

Media Pack ZIP Export

The Media Editor can generate a ZIP archive containing: all raw uploaded photos, optimized/cropped images, PDF documents, a metadata JSON file with activity details, and the AI-generated caption. The ZIP is assembled on-the-fly and streamed to the browser for download.
